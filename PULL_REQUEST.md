# SarmatDTC 1.1.13: защищённые данные карты, новые модули и безопасные обновления DTC

## Область PR

Этот накопительный PR описывает все изменения, сделанные **после PR #3** (HEAD `908b959f4de97039e35ab8582b65324fbecb23a2`). Входят версии **1.1.2–1.1.13**. Итоговая версия модуля — **1.1.13**.

PR #2 и PR #3 на момент подготовки остаются открытыми, поэтому при создании нового PR в `std-glimmer/sarmat-dtc-generator:main` GitHub также покажет прежние коммиты из этих PR. Новый коммит и этот документ относятся именно к изменениям после состояния PR #3.

## Краткое резюме

- Добавлена поддержка обновлённой живой карты: наземные группы загружаются через защищённый `/api/side_data` с Website code; скрытые сервером противники не восстанавливаются на клиенте.
- Для F/A-18C добавлены независимые западная, центральная и восточная линии FLOT.
- Для AH-64D, F-14B(U), F-16C и F/A-18C добавлена необязательная выгрузка **DTC for DCS только с ППМ** в стандартные папки пресетов.
- F-15E теперь автоматически получает картридж Modern F-15E и необязательные границы секторов на SIT.
- В конфигуратор добавлены полноценные разделы F-14B(U) и AH-64D.
- AH-64D получил две миссии фронта, плотный отбор точек, объединение групп, AREA для крупных скоплений, OP/Depot и короткие FREE-подписи.
- Добавлено обновление после посадки на своей базе, а затем безопасный режим по умолчанию: обновление только при респавне или смене слота. Обновление после посадки включается отдельно в HTML.
- Из обработчика посадки удалены синхронный запрос к миссии DCS и немедленная повторная генерация.

## 1. Обновлённая живая карта и Website code

После обновления карты публичный `units.json` больше не отдаёт координаты наземных групп. Добавлена настройка `MAP_CODE` в `config.user.lua`:

```lua
return {
    MAP_CODE = "ВАШ_КОД",
}
```

Код получается на сервере через **F10 → Settings → Website code**. Если он задан, `fetch.vbs`/`fetch.cmd` вместо публичного `units.json` загружают `/api/side_data?code=...&sid=sarmat-dtc` (на Кавказе — `/k/api/side_data`).

Реализация:

- ответ `side_data` преобразуется в прежнюю нейтральную структуру `{ groups = ... }`;
- остаются свои группы и противники с `foe = true`; скрытые сервером позиции отбрасываются;
- несовпадение стороны кода и слота отклоняет генерацию;
- обрабатываются неверный/погашенный код, отсутствие привязки к стороне и блокировка;
- код не выводится в `dcs.log` и не включается в поставку;
- без кода по-прежнему строятся фронт, объекты и статические ЗРК, а в чат выводится понятное предупреждение вместо сотен ошибок о битых записях;
- сохранены атомарная пара кэша, ограничения HTTPS, размер ответа, таймауты и повторные попытки.

Добавлены фикстура `side_data.json`, офлайн-проверки нормализации и фильтрации, а также поддержка тестового `file://`-endpoint в `run_tests.ps1`/`test_hook.lua`.

## 2. F/A-18C Hornet

Для `FLOT_1`, `FLOT_2`, `FLOT_3` добавлены независимые источники:

- `FRONT_WEST` — западная треть ЛБС;
- `FRONT_CENTER` — центральная треть;
- `FRONT_EAST` — восточная треть;
- прежние `FRONT`, сектора и `NONE` сохранены.

Части вычисляются по диапазону долготы фронта. На стыках добавляются общие интерполированные точки, поэтому соседние линии соединяются без разрывов. Если извилистая ЛБС несколько раз входит в одну треть, используется самый длинный непрерывный участок без соединительной линии через карту. Каждая линия независимо упрощается до лимита в 7 точек. Географические части доступны только FLOT, не FAOR/CORRIDORS.

Пример:

```lua
OPTIONS = {
    ["FA-18C_hornet"] = {
        FLOT_1 = "FRONT_WEST",
        FLOT_2 = "FRONT_CENTER",
        FLOT_3 = "FRONT_EAST",
        DEFAULT_FLOT = 1,
    },
}
```

Все назначения доступны в HTML-конфигураторе. Добавлен отдельный waypoint-only пресет DTC for DCS, описанный ниже.

## 3. Пресеты DTC for DCS — только ППМ

Для четырёх модулей добавлен выход `dcs-dtc-waypoints`. Он выключен по умолчанию и создаёт `SARMAT.json` формата **DTC for DCS Version 2** в стандартной папке приложения:

| Модуль | Папка в `Документы\DCS-DTC\Presets\` | Содержимое |
|---|---|---|
| AH-64D | `AH64D` | Выбранные аэродромы, FARP/FOB, OP, стронгхолды и группы, WP 1–50 |
| F-14B(U) | `F14BU` | Свои аэродромы и FARP/FOB, ППМ 51–99 |
| F-16C | `F16C` | Выбранные DEST-объекты с новой последовательной нумерацией |
| F/A-18C | `FA18C` | Объединённые GPS1/GPS2 в ППМ 1–59; ППМ 0 свободен |

Включается только `Upload.Waypoints`: радио, CMDS, MFD, линии, угрозы и другие разделы приложения не выгружаются. Основные нативные картриджи DCS не заменяются этим выходом.

Включение в существующих блоках `OPTIONS`:

```lua
["AH-64D_BLK_II"] = { outputs = { ["dcs-dtc-waypoints"] = { enabled = true } } },
["F-14BU"]        = { outputs = { ["dcs-dtc-waypoints"] = { enabled = true } } },
["F-16C_50"]      = { outputs = { ["dcs-dtc-waypoints"] = { enabled = true } } },
["FA-18C_hornet"] = { outputs = { ["dcs-dtc-waypoints"] = { enabled = true } } },
```

Для нестандартного `StorageFolder` в `dtc.ini` можно задать тот же путь через `OPTIONS[тип].outputs["dcs-dtc-waypoints"].dir`. Существующий расширенный пресет F-15E не изменяется этим режимом.

## 4. F-15E Strike Eagle / Modern F-15E

### Автоматический картридж Modern F-15E

Добавлен выход `f15e-modern`: готовый `SARMAT.json` автоматически записывается в `ModernF15E\Cartridges` внутри профиля DCS. Прежний пресет `Документы\DCS-DTC\Presets\F15E\SARMAT.json` сохранён. Оба выхода используют один построенный документ, поэтому маршруты, настройки и GeoJSON совпадают.

Ручной импорт через **DTM Cartridges…** больше не нужен. В кабине по-прежнему необходимо выбрать `SARMAT` и выполнить **MC DTM → LOAD** с включённым **DRAW** на каждом новом борту.

### Границы секторов на SIT

Добавлен необязательный слой `SARMAT sectors.geojson`:

- `SECTOR_SOURCE`: `NONE`, `ACTIVE_SECTORS`, `OWN_SECTORS`, `ENEMY_SECTORS`, `ALL_SECTORS`;
- `SECTOR_COLOR` — цвет контура;
- `SECTOR_STYLE` — `solid`, `dash`, `dot`, `dotdash`.

Каждая граница записывается замкнутым GeoJSON Polygon с не более чем 64 координатами. По умолчанию слой выключен (`NONE`), поэтому старые картриджи не меняются без включения.

У Modern F-15E общий лимит — 32 фигуры, включая рисунки миссии. Внутри картриджа SARMAT приоритет задан так: линия фронта, сектора, затем кольца угроз. Оба выхода F-15E получают одинаковый слой без дублирования builder.

## 6. AH-64D Apache

### Две миссии фронта

Основной картридж разделён на:

- **Mission 1** — западная половина ЛБС;
- **Mission 2** — восточная половина ЛБС.

Полилинии имеют общую интерполированную точку стыка. Точки и угрозы отбираются только для своей половины. Каждая миссия независимо получает до 50 WPT, 49 CTRLM, 12 AREAs и 25 TGT, поэтому доступные точки размещаются плотнее, а не распределяются по всей длине фронта. Для вырожденной ЛБС без протяжённости по долготе сохранён одномиссионный резервный режим.

### Аэродромы и FARP/FOB в WPT

Аэродромы и FARP/FOB обеих сторон перенесены из Control Measures в нативные **WPTHZ/WP 1–50** и больше не занимают CTRLM. Свои места посадки имеют приоритет. `WPTHZ_PTS` задаёт лимит; `0` отключает создание таких WPT. Общий фильтр дистанции от ЛБС действует и на них.

### OP и Depot

- OP из `status.strong` выводятся в CTRLM символом FC.
- Depot из `status.depots3` выводятся только при `alive > 0`; уничтоженные пропускаются.
- OP/Depot проходят фильтр своей миссии, дистанции от ЛБС и общий отбор по приоритету.
- Полное имя и сторона сохраняются в примечании точки.

### Группы войск и дистанционные фильтры

- Все нативные WPT/CTRLM/TGT по умолчанию ограничены **10 км от ЛБС** (`AO_DEPTH_M`).
- Оставшиеся группы одной стороны ближе **1 км** объединяются (`CLUSTER_M`); юниты суммируются.
- Класс объединённой метки выбирается по преобладающему числу машин в общем составе.
- Свои и вражеские группы не объединяются; группа рядом с FARP остаётся самостоятельной CTRLM.
- Свои войска по умолчанию ограничены `OWN_FRONT_M = 10000`; свои ПВО скрыты (`OWN_AD = false`).
- Приоритет учитывает расстояние до фронта, базу спавна/последней принятой посадки и повышенный вес вражеских объектов.
- Радиусы задаются в метрах; `0` снимает соответствующее ограничение или объединение.

### Крупные скопления как AREA

Скопление одной стороны от **5 групп**, связанных дистанцией до **3 км**, заменяется одной четырёхугольной AREA:

- прямоугольник охватывает позиции с отступом 500 м;
- в центре обязательно ставится одна CTRLM с классом и числом исходных групп;
- представленные AREA группы не дублируются обычными CTRLM или вражескими TGT;
- `AREA_MIN_GROUPS` и `AREA_DIST_M` настраиваются в HTML;
- `0` любого параметра или `CTRLM = 0` отключает AREA.

### FREE-текст до трёх символов

- Аэродром: первые три буквы без ведущего `AL-`/`AN-`, например `Al-Dumayr → DUM`.
- FARP: `F` и номер без номера площадки, например `FARP 22-1 → F22`.
- OP/Depot: `O<номер>`/`D<номер>`, например `O10`, `D10`.
- Группы: `T` — танки, `A` — артиллерия, `C` — смешанные/механизированные/пехотные/прочие, `S` — ПВО; далее число юнитов, например `T4`, `C12`.
- Центр AREA: класс и число исходных групп, например `T5`, `C5`.
- Статическая площадка ПВО без живого состава получает `SAM`.

Полное имя и сторона остаются в `note`. Экипажу оставлены T26–T50 для сохранения собственных точек.

### Отдельный пресет DTC for DCS

Waypoint-only пресет AH-64D настраивается независимо от основного картриджа:

- `WP_PTS` — лимит WP 1–50;
- `WP_NM` — дистанция от ЛБС;
- `WP_SOURCES` — `AIRFIELDS`, `FARPS`, `STRONGPOINTS`, `STRONGHOLDS`, `GROUPS`;
- `WP_SIDE` — `OWN`, `ENEMY`, `ALL`;
- `WP_ORDER` — порядок отбора.

При включении по умолчанию выбраны все пять категорий и обе стороны. Сам выход по-прежнему выключен по умолчанию. Для наземных групп требуется `MAP_CODE`, сервер выдаёт только разрешённых противников.

## 7. Обновление при посадке и безопасный режим

### Версия 1.1.12

Добавлено событие `onGameEvent('landing', ...)`: после посадки своего игрока на аэродроме или FARP своей коалиции база становится новым центром приоритета и запускается обновление DTC. Проверяется только сторона базы, без запроса складов, топлива и вооружения. Повтор события отсеивается 15 секунд, параллельная загрузка не создаётся.

### Версия 1.1.13

После сообщения о возможных фризах прежний режим возвращён и сделан безопасным значением по умолчанию:

```lua
LANDING_REFRESH = false
```

- При `false` обработчик посадки сразу завершается: нет обращений к DCS, разбора JSON, генерации или записи. Файлы обновляются только при респавне или смене слота.
- В общий раздел HTML добавлен переключатель **«Обновлять DTC после посадки»**.
- При `true` база и коалиция определяются по кэшированным данным карты: `loadCache` → разбор только `status.json` → `core.situation` → точное имя среди своих `airfields`/`farps`.
- Синхронный `net.dostring_in('mission', …)` удалён.
- Немедленная `generate(false)` при посадке удалена. База меняет `state.spawn`, затем запускается `startFetch(true)`.
- Единственная генерация происходит после завершения, ошибки или таймаута загрузки. Активная загрузка не дублируется, а её завершение использует новый центр.
- Небулево значение настройки отклоняется с предупреждением.

Это устраняет найденные источники дополнительной работы на GUI-потоке, но отсутствие фризов в реальной DCS должно быть подтверждено отдельной проверкой.

## 8. HTML-конфигуратор

- Сохранены вкладки F-15E, F/A-18C и F-16C; добавлены F-14B(U) и AH-64D.
- Добавлен всегда доступный общий раздел вне самолётных вкладок.
- Все новые настройки читаются из существующего `config.user.lua` и сохраняются обратно без дублирования блоков.
- Посторонние параметры, комментарии, `BASE_DTC` и другие пользовательские данные сохраняются.
- `LANDING_REFRESH` обрабатывается на верхнем уровне файла, вне `OPTIONS`; вручную заданный `MAP_CODE` сохраняется как посторонняя пользовательская настройка.
- Старые конфиги без новых полей получают безопасные значения по умолчанию.
- Прямая запись через File System Access API и скачивание готового файла используют одинаковую логику генерации.

## Совместимость и значения по умолчанию

- Существующие `config.user.lua` остаются рабочими; новые поля необязательны.
- `MAP_CODE` по умолчанию пуст, личный код не входит в поставку и не логируется.
- Все четыре новых выхода `dcs-dtc-waypoints` выключены по умолчанию.
- Слой границ секторов F-15E выключен по умолчанию.
- `LANDING_REFRESH = false` по умолчанию: посадка не обрабатывается.
- Пользовательский `config.user.lua` не перезаписывается установкой.
- Дополнительные форматы используют существующие `outputs`, кодировщики и атомарную запись.
