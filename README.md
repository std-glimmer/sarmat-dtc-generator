# SarmatDTC — генератор DTC для серверов SARMAT (DCS World)

На сервере, в названии которого есть **SARMAT**, мод берёт обстановку с
[живой карты](https://baikalprimestudio.com/map.html) и сам создаёт картриджи DTC
для вашей коалиции при респавне или смене слота: линию фронта, вражеские ЗРК, группы войск
и FARP-ы. Отдельная настройка включает обновление после посадки на базе своей коалиции.
Работает на Сирии и Кавказе.

- [Для игроков](#для-игроков): установка, использование, настройки, проблемы
- [Для разработчиков](#для-разработчиков): устройство, новые модули, тесты

# Для игроков

## Что попадает в картридж

| Модуль | Файл | Что размечается |
|---|---|---|
| AH-64D | `SARMAT_AH-64D_BLK_II.dtc` | **Mission 1 / 2**: западная / восточная половина ЛБС. В каждой **Waypoints** (WP 1–50): аэродромы и FARP/FOB; **Control Measures** (C51–C99): группы, центры AREA, OP и живые Depot; **Areas**: крупные скопления групп; **Targets** (T01–T25): вражеские ПВО; **Lines**: своя половина фронта (FLOT) |
| F-16C | `SARMAT_F-16C_50.dtc` | **GEO LINES**: линия фронта (до 25 точек). **THREAT PTS**: вражеские ЗРК с кольцами (до 15) |
| F/A-18C | `SARMAT_FA-18C_hornet.dtc` | **SA → FLOT**: вся линия фронта или её западная/центральная/восточная треть (3 линии × 7 точек). **SA → MEZ THRTS**: вражеские ЗРК с кольцами (до 40) |
| F-14B(U) | `SARMAT_F-14BU.dtc` | Линия фронта в навигационном плане 1 |
| F-15E | `Документы\DCS-DTC\Presets\F15E\SARMAT.json` и `ModernF15E\Cartridges\SARMAT.json` | Маршруты A/B/C, линия фронта, необязательные границы секторов и настройки для мода Modern F-15E; обе копии обновляются автоматически |

Копия `ModernF15E\Cartridges` создаётся в профиле DCS (`lfs.writedir()`). Ручной импорт через
**DTM Cartridges…** не требуется: в кабине выберите `SARMAT` на странице **MC DTM** и нажмите
**LOAD** с включённым **DRAW**. На новом борту загрузку нужно выполнить снова. Ручные изменения
этого файла перезаписываются при генерации.

Файлы DCS лежат в `Saved Games\DCS.openbeta\DTC\` (у новых установок — `Saved Games\DCS\DTC\`;
другую папку можно задать в [настройках](#папка-для-картриджей)) и перезаписываются при респавне
или смене слота. Если включена `LANDING_REFRESH`, они также обновляются после принятой посадки.
Всё остальное в картридже (радио, CMDS, лазерные коды, маршруты) остаётся по умолчанию DCS
или берётся из вашего [базового картриджа](#базовый-картридж).

### AH-64D: картинка TSD на один вылет

Apache получает не всю карту, а то, что важно для вылета с вашей базы:

- аэродромы и FARP/FOB обеих сторон записываются в WPTHZ как обычные WP 1–50 и не занимают CTRLM;
  свои места посадки идут первыми, `WPTHZ_PTS` задаёт лимит (0 — не создавать WPT);
- OP и Depot с `alive > 0` записываются в CTRLM символом FC и участвуют в общем отборе точек;
- только точки не дальше 10 км от ЛБС; при известной базе также действует район вылета от неё;
- скопление от 5 групп одной стороны, связанных дистанцией до 3 км, заменяется четырёхугольной
  AREA с отступом 500 м и одной обязательной CTRLM в центре;
- для остальных групп действует один символ на позицию: группы одной стороны ближе 1 км сливаются,
  юниты суммируются, а класс метки определяется по преобладающему числу машин в общем составе;
- свои войска — только в 10 км от фронта (чтобы не стрелять по своим), свои ПВО не показываются;
- приоритет — у объектов ближе к фронту и к вашей базе, вражеские войска важнее своих.

Порог и дистанцию AREA можно изменить в HTML; значение 0 любого параметра отключает AREA.
Во всех точках FREE-текст не длиннее трёх символов. Аэродром — первые три буквы без ведущего
`AL-`/`AN-` (`Al-Dumayr` → `DUM`), FARP — `F` и номер без номера площадки (`FARP 22-1` → `F22`),
OP/Depot — `O10`/`D10`. Группы обозначаются типом и числом юнитов: `T` — танки, `A` — артиллерия,
`C` — смешанные/механизированные/пехотные/прочие, `S` — ПВО (`T4`, `C12`). В центре AREA число
показывает исходные группы (`T5`, `C5`), у статической площадки ПВО без живого состава — `SAM`.
Полное имя и сторона указаны в заметке точки на странице POINT. Заполняются только T01–T25: точки,
которые экипаж сохраняет в кабине, попадают в свободные T26–T50.

### F-16C и F/A-18C: кольца ЗРК

Берутся вражеские ЗРК с радиусом от 6 км (ЗУ, ПЗРК, SA-9/13 и Avenger отсекаются), одно кольцо
одного типа в радиусе 5 км. Сначала идут кольца, которые ближе всего к фронту или перекрывают его.

### Пресеты приложения DTC for DCS — только ППМ

Для AH-64D, F-14B(U), F-16C и F/A-18C есть дополнительный выход `dcs-dtc-waypoints`.
Он создаёт `SARMAT.json` в стандартной папке приложения:

| Модуль | Папка в `Документы\DCS-DTC\Presets\` | Источник и номера ППМ |
|---|---|---|
| AH-64D | `AH64D` | Аэродромы, FARP/FOB, опорные пункты, стронгхолды и группы юнитов выбранных сторон, WP 1–50 |
| F-14B(U) | `F14BU` | Свои аэродромы и FARP/FOB, ППМ 51–99 |
| F-16C | `F16C` | Выбранные DEST-объекты, перенумерованные с 1 |
| F/A-18C | `FA18C` | GPS1 + GPS2, перенумерованные 1–59; ППМ 0 свободен |

У AH-64D при включении по умолчанию выбраны все пять категорий и обе стороны. В конфигураторе можно
изменить набор, сторону, дистанцию от ЛБС, порядок и лимит. Для наземных групп нужен `MAP_CODE`;
сервер выдаёт только разрешённых противников. Основной картридж Control Measures/Targets не изменён.

В JSON включается только `Upload.Waypoints`: радио, CMDS, MFD, линии, угрозы и прочие разделы
не выгружаются. Эти четыре выхода по умолчанию выключены. Для включения добавьте в существующие
блоки `OPTIONS` файла `config.user.lua` (не создавайте повторный блок того же самолёта):

```lua
["AH-64D_BLK_II"] = { outputs = { ["dcs-dtc-waypoints"] = { enabled = true } } },
["F-14BU"]        = { outputs = { ["dcs-dtc-waypoints"] = { enabled = true } } },
["F-16C_50"]      = { outputs = { ["dcs-dtc-waypoints"] = { enabled = true } } },
["FA-18C_hornet"] = { outputs = { ["dcs-dtc-waypoints"] = { enabled = true } } },
```

Пресет обновляется вместе с остальными файлами при выборе слота. В DTC for DCS выберите `SARMAT`.
Если список пресетов уже был открыт, переоткройте его после первой генерации. При нестандартном
`StorageFolder` в `dtc.ini` задайте тот же путь в `OPTIONS[тип].outputs["dcs-dtc-waypoints"].dir`.
Существующий расширенный пресет F-15E (`f15e-dtc`) этот режим не изменяет.

## Требования

- Windows 10/11 (используется встроенный `curl.exe`);
- DCS World (Сирия или Кавказ), сервер с **SARMAT** в названии.

## Установка

1. Найдите папку DCS в `Saved Games`: та, где есть `Logs\dcs.log`. Обычно это
   `%USERPROFILE%\Saved Games\DCS\` (DCS 2.9+) или `%USERPROFILE%\Saved Games\DCS.openbeta\`.
2. Скопируйте в неё папку `Scripts` из репозитория (с объединением папок).
3. Запустите DCS. В `Logs\dcs.log` должна появиться строка `SARMAT.DTC ... loaded, version ...`.

**Обновление** — скопируйте `Scripts` заново. Ваш `config.user.lua` сохранится: его нет в поставке.
**Удаление** — удалите `Scripts\Hooks\SarmatDTC-hook.lua` и папку `Scripts\SarmatDTC`.

## Как пользоваться

1. Подключитесь к серверу SARMAT. Мод сразу начнёт фоново скачивать карту (обычно несколько секунд, игра не тормозит).
2. Выберите слот. Картриджи для вашей стороны пишутся сразу из последних данных, а после свежей
   загрузки — ещё раз. По умолчанию следующие обновления происходят только при респавне или смене слота.
3. Если нужно обновление после посадки, включите «Обновлять DTC после посадки» в общем разделе
   конфигуратора или задайте `LANDING_REFRESH = true` в `config.user.lua`. Тогда посадка на аэродроме
   или FARP своей коалиции меняет центр приоритета и запускает загрузку карты. База определяется по
   кэшированным данным карты; склады, топливо и вооружение не проверяются. Синхронного запроса к
   миссии DCS и немедленной генерации из кэша нет: файлы перестраиваются один раз после завершения
   загрузки, также при её ошибке или таймауте.
4. В чате появится локальное сообщение (его видите только вы), например
   `SarmatDTC: BLUE DTC ready (Hatay): AH-64D, F-16C, FA-18C` — сторона, текущая база, модули.
5. Загрузите `SARMAT_<модуль>` в менеджере DTC перед вылетом.

Если обстановка на карте и база не поменялись с прошлой записи, файлы не перезаписываются и в чат ничего не пишется.

### Сообщения в чате

| Пометка | Что значит |
|---|---|
| `- download failed` / `- download timed out` | Сайт не ответил, картриджи построены из прошлой загрузки |
| `- map data 25 min old` | Данным больше 10 минут: обстановка могла измениться |
| `- website code required for ground units` | В `MAP_CODE` не задан код: фронт и объекты записаны, наземных групп нет |
| `website code not recognised / expired` | Код неверен или погашен; возьмите новый в DCS и обновите `MAP_CODE` |
| `website code is not bound to a side` | Код ещё не привязан: войдите в слот на сервере и повторите |
| `- 1 error(s), see dcs.log` | Один из модулей не собрался, остальные записаны |
| `..., no DTC written` | Ничего не записано (например, данные старше 3 часов или с другой карты). Файл `SARMAT_*.dtc` на диске при этом **устарел** |

## Настройки — `Scripts\SarmatDTC\config.user.lua`

`config.lua` — настройки по умолчанию, при обновлении он заменяется. Свои настройки пишите
в `config.user.lua` рядом с ним (создайте файл сами). Указывайте только то, что меняете:
`AIRCRAFT`, `DTC_DIR`, `MAP_CODE` и `LANDING_REFRESH` заменяют значения из `config.lua`,
`BASE_DTC` и `OPTIONS` — по отдельным самолётам.

```lua
-- Scripts/SarmatDTC/config.user.lua
return {
    AIRCRAFT = {             -- для каких самолётов генерировать
        "AH-64D_BLK_II",
        "F-16C_50",
    },
    DTC_DIR = "DTC\\SARMAT", -- папка для картриджей (по умолчанию "DTC")
    MAP_CODE = "AB2C3D",     -- код из DCS: F10 → Settings → Website code
    LANDING_REFRESH = false, -- true: также обновлять после посадки на своей базе
    BASE_DTC = {             -- ваш картридж: из него берётся всё, что мод не заполняет
        ["AH-64D_BLK_II"] = "AH-64D_BLK_II_DTC_SAR_3.dtc",
    },
    OPTIONS = {              -- опции модулей (таблицы ниже)
        ["AH-64D_BLK_II"] = { WPTHZ_PTS = 50, TGT = 50 },
        ["FA-18C_hornet"] = { THREATS = 0 },
        ["F-14BU"]        = { enabled = false },
    },
}
```

Файлы перечитываются при каждом старте миссии, перезапускать DCS не нужно. Ошибка в
`config.user.lua` — предупреждение в `dcs.log`, тогда используется только `config.lua`.
Значение опции вне допустимых границ прижимается к ним (с предупреждением в логе).
`LANDING_REFRESH` принимает только `true` или `false`; переключатель также есть в общем разделе
HTML-конфигуратора. Выключенное значение полностью исключает обработку посадки.

### Website code для наземных групп

После обновления живой карты публичный `units.json` больше не содержит координат наземных групп.
Чтобы мод получал свои группы и видимых противников, откройте на сервере **F10 → Settings → Website code**
и укажите код в `config.user.lua`:

```lua
return {
    MAP_CODE = "ВАШ_КОД",
    -- остальные ваши настройки оставьте как были
}
```

Код привязывается к стороне после входа в слот. Если вы получили новый код или сменили сторону,
замените `MAP_CODE`. Код не пишется в `dcs.log`. Без него мод по-прежнему строит линию фронта,
объекты и статические ЗРК, но наземные группы не добавляет и показывает пометку `website code required`.
Мод получает только тех противников, которых сервер карты считает видимыми (`foe`); скрытые позиции
восстановить на клиенте нельзя.

### Папка для картриджей

`DTC_DIR` — куда писать `SARMAT_<тип>.dtc`. Путь относительно `Saved Games\DCS.openbeta`
(`"DTC\\SARMAT"`), полный (`"D:\\DCS DTC"`, `"\\\\server\\share"`) или с `%ENV%`. В строках Lua
обратную косую черту нужно удваивать. Папка создаётся сама. Импорт в менеджере DTC открывает
`Saved Games\...\DTC\`: перейдите в нужную папку в этом окне. Для одного самолёта папку можно
задать отдельно: `OPTIONS[тип].outputs["dcs-dtc"].dir` (см. [Опции](#опции)). Базовые картриджи
(`BASE_DTC`) по-прежнему ищутся в `Saved Games\...\DTC\`: туда их сохраняет редактор DTC.

### Базовый картридж

`BASE_DTC[тип]` — обычный DCS-картридж, сохранённый в редакторе DTC: имя файла из папки `DTC`
или полный путь. Мод берёт его копию и заменяет только свою разметку (фронт, угрозы, точки).
Навигация базового файла, сделанного на другой карте, не используется, остальные настройки — да.
Указывать сам `SARMAT_<тип>.dtc` нельзя.

### Опции

Общие для всех модулей: `enabled = false` — не генерировать; `outputs = { ["dcs-dtc"] = { dir = "...", file = "..." } }` —
другая папка или имя файла (подстановки `{type}`, `{side}`, `{terrain}`; путь относительно
`Saved Games\DCS.openbeta`, абсолютный или с `%ENV%`).

**AH-64D** (`AH-64D_BLK_II`)

| Опция | По умолч. | Границы | Смысл |
|---|---|---|---|
| `WPTHZ_PTS` | 50 | 0–50 | Аэродромы и FARP/FOB в нативных WP 1–50; 0 — не создавать |
| `CTRLM` | 49 | 0–49 | Число Control Measures: группы войск, центры AREA, OP и живые Depot |
| `TGT` | 25 | 0–50 | Число Targets/Threats. Больше 25 — экипажу негде сохранять свои точки |
| `LINES` / `LINE_PTS` | 15 / 4 | 0–15 / 2–4 | Линии фронта и вершин в линии |
| `AO_DEPTH_M` | 10000 | ≥ 0 | Максимальная дистанция нативных WPT/CTRLM/TGT от ЛБС, м (0 — вся карта) |
| `CLUSTER_M` | 1000 | ≥ 0 | Радиус объединения групп, м (0 — без объединения) |
| `AREA_MIN_GROUPS` | 5 | 0–49 | Минимум связанных групп одной стороны для AREA (0 — отключить) |
| `AREA_DIST_M` | 3000 | ≥ 0 | Максимальная дистанция связи между группами AREA, м (0 — отключить) |
| `OWN_FRONT_M` | 10000 | ≥ 0 | Свои войска не дальше этого от фронта, м (0 — все) |
| `OWN_AD` | false | — | Показывать свои ПВО |
| `SPAWN_WEIGHT` | 0.5 | ≥ 0 | Вес расстояния до базы спавна (0 — не учитывать) |
| `ENEMY_FACTOR` | 0.7 | ≥ 0 | Множитель веса вражеских (1 — без предпочтения) |
| `RING_CAP_M` | 15000 | ≥ 0 | Максимум кольца угрозы при сортировке Targets, м |
| `WP_PTS` | 50 | 0–50 | Лимит ППМ отдельного пресета DTC for DCS; 0 — не записывать |
| `WP_NM` | 0 | ≥ 0 | Дистанция ППМ от ЛБС, NM; 0 — без ограничения |
| `WP_SOURCES` | все пять категорий | — | `AIRFIELDS`, `FARPS`, `STRONGPOINTS`, `STRONGHOLDS`, `GROUPS` через запятую |
| `WP_SIDE` | `ALL` | — | Стороны объектов waypoint-only пресета: `OWN`, `ENEMY`, `ALL` |
| `WP_ORDER` | `FRONT` | — | Порядок ППМ, как у других правил точек |

Вся карта без отбора: `{ TGT = 50, AO_DEPTH_M = 0, CLUSTER_M = 0, OWN_FRONT_M = 0, OWN_AD = true }`.

**F-16C** (`F-16C_50`)

| Опция | По умолч. | Границы | Смысл |
|---|---|---|---|
| `POINTS` | 25 | 2–25 | Точек линии фронта |
| `THREATS` | 15 | 0–15 | Колец ЗРК (0 — оставить угрозы из миссии) |
| `MIN_RANGE` | 6000 | ≥ 0 | Минимальный радиус ЗРК, м |
| `DEDUP_M` | 5000 | ≥ 0 | Одно кольцо одного типа в этом радиусе, м |

**F/A-18C** (`FA-18C_hornet`)

| Опция | По умолч. | Границы | Смысл |
|---|---|---|---|
| `FLOT_1` / `FLOT_2` / `FLOT_3` | `NONE` | — | Назначение каждой линии FLOT: `FRONT`, `FRONT_WEST`, `FRONT_CENTER`, `FRONT_EAST` или сектор |
| `FAOR_1` / `FAOR_2` / `FAOR_3` | `NONE` | — | `FRONT`, `ACTIVE_SECTORS`, `OWN_SECTORS`, `ENEMY_SECTORS`, `ALL_SECTORS` или `NONE` |
| `CORRIDOR_1` … `CORRIDOR_7` | `FRONT`, далее `NONE` | — | Те же источники, что у FAOR |
| `CORRIDOR_PTS` | 14 | 2–14 | Максимум точек в коридоре; у FAOR/FLOT фиксированный лимит 7 |
| `THREATS` | 40 | 0–40 | Колец ЗРК (0 — оставить угрозы из миссии) |
| `MIN_RANGE` / `DEDUP_M` | 6000 / 5000 | ≥ 0 | Как у F-16C |
| `THREAT_LEVEL` | 1 | 1–3 | Уровень угрозы колец |
| `DEFAULT_FLOT` | 4 | 1–4 | Линия FLOT по умолчанию на странице SA (4 — NONE) |

Пример разметки `FLOT 1 — запад`, `FLOT 2 — центр`, `FLOT 3 — восток`:

```lua
OPTIONS = {
    ["FA-18C_hornet"] = {
        FLOT_1 = "FRONT_WEST",
        FLOT_2 = "FRONT_CENTER",
        FLOT_3 = "FRONT_EAST",
        DEFAULT_FLOT = 1,
    },
}
```

Трети вычисляются по диапазону долготы ЛБС. На стыки добавляются общие расчётные точки,
поэтому линии соединяются без разрывов. Если извилистый фронт несколько раз входит в одну
треть, используется самый длинный непрерывный участок, без соединительных линий через карту.

**F-15E** (`F-15ESE`)

| Опция | По умолч. | Смысл |
|---|---|---|
| `SECTOR_SOURCE` | `NONE` | Границы на SIT: `ACTIVE_SECTORS` (через ЛБС), `OWN_SECTORS`, `ENEMY_SECTORS`, `ALL_SECTORS` или `NONE` |
| `SECTOR_COLOR` | `#FFFFFF` | Цвет границ секторов |
| `SECTOR_STYLE` | `dot` | Тип контура: `solid`, `dash`, `dot`, `dotdash` |
| `FRONT_COLOR` / `FRONT_STYLE` | `#FF0000` / `solid` | Цвет и тип линии фронта |
| `THREATS` | 0 | Дополнительные кольца ЗРК; 0 — использовать штатные кольца Modern F-15E |

Границы записываются замкнутыми полигонами с не более чем 64 координатами. Modern F-15E
показывает максимум 32 фигуры, включая рисунки миссии; в картридже SARMAT приоритет такой:
фронт, сектора, затем кольца угроз. Оба выхода F-15E содержат одинаковый документ. После
генерации в кабине нужен **MC DTM → SARMAT → LOAD** с включённым **DRAW** на каждом новом борту.

**F-14B(U)** (`F-14BU`): `LINES` 2 (1–4), `LINE_PTS` 9 (2–9); всего не больше 20 точек на план.

## Если не работает

Откройте `Saved Games\DCS.openbeta\Logs\dcs.log` и найдите строки `SARMAT.DTC`.

| Симптом | Причина / что делать |
|---|---|
| Нет строки `loaded, version` | Мод не установлен в ту папку `Saved Games` (см. [Установка](#установка)) |
| Нет сообщения в чате | В названии сервера нет «SARMAT», выбран слот зрителя или модуль не в `AIRCRAFT` |
| Нет наземных групп, фронт и ЗРК есть | Обновлённая карта требует `MAP_CODE`; проверьте код и его привязку к стороне |
| `download failed (...: curl exit 28, timeout)` | Сайт карты не ответил; повторите выбор слота через минуту |
| `base DTC is for another map, not used` | Базовый картридж сделан на другой карте, его навигация пропущена |
| `config.lua option: ... out of range` | Опция вне границ, использовано ближайшее допустимое значение |

Ручная проверка загрузки (из папки `Saved Games\DCS.openbeta`):

```powershell
wscript //B //Nologo Scripts\SarmatDTC\fetch.vbs https://baikalprimestudio.com/data/
```

Результат — `Scripts\SarmatDTC\cache\done-manual.flag` (`ok` или `fail <файл> <код curl>`).

> **Безопасность.** `config.lua`, `config.user.lua` и файлы в `aircraft/` — код на Lua, который DCS
> выполняет с полным доступом к системе. Не кладите модули от незнакомых людей и не вставляйте чужой
> `config.user.lua`, не прочитав его. Данные сайта кодом не являются: они только разбираются как JSON,
> битые записи пропускаются, ответ больше 5 МБ не принимается.

Полный справочник по устройству, принятым решениям и ловушкам окружения — [AGENTS.md](AGENTS.md).
API модуля — в [`aircraft/_template.lua`](Scripts/SarmatDTC/aircraft/_template.lua).

## Файлы

| Путь | Назначение |
|---|---|
| `Scripts/Hooks/SarmatDTC-hook.lua` | Загрузчик (DCS исполняет `Scripts/Hooks/*` в GUI-окружении) |
| `Scripts/SarmatDTC/SarmatDTC.lua` | Связь с DCS: колбэки, сервер и сторона, загрузка, кэш, кодировщики, запись файлов. `CONFIG` и `VERSION` в начале |
| `Scripts/SarmatDTC/SarmatDTC_core.lua` | Библиотека без DCS: данные карты → `situation`, классификация юнитов и ПВО, геометрия, загрузка и запуск модулей, базовый картридж |
| `Scripts/SarmatDTC/aircraft/<type>.lua` | Один файл на модуль DCS, подхватывается автоматически (`_*.lua` пропускаются) |
| `Scripts/SarmatDTC/config.lua` | Настройки по умолчанию; поверх — `config.user.lua` игрока |

`.gitignore` — allowlist: репозиторий лежит в самой папке `Saved Games\DCS.openbeta`, новый файл
нужно разрешить строкой `!путь`.

## Поток данных

```
onMissionLoadEnd ── сервер SARMAT? ──► fetch.vbs → fetch.cmd → curl ──► cache/*-<id>.part + done-<id>.flag
onSimulationFrame ── флаг ok ──► status.json + units.json (ставятся на место парой)
onPlayerChangeSlot ── сторона, база спавна ──► generate:
    loadCache → inputKey (без изменений — выход) → decodeCache → core.situation()
      → aircraft/<type>.lua: build → "dcs-dtc" (+ BASE_DTC), outputs → другие форматы
      → ENCODERS (dcs-dtc / json / lua / text) → writeFileAtomic → чат и dcs.log
```

- `situation` нейтральна: ключи классов (`"SA-11"`, `"armor"`), координаты DCS x/z, без символов
  конкретных самолётов. Символы и лимиты — только в файле модуля.
- Каждый модуль, выход и колбэк выполняется в `pcall`: сбой одного не ломает остальные и GUI игры.
- Данные сайта не доверенные: записи без числовых координат пропускаются и считаются.

## Новый модуль

1. Найти `CoreMods/aircraft/<module>/DTC/` в установке DCS: `<type>_DTC.lua` (`type`, `setData`,
   `mirror_*`, проверка `terrain`) и лимиты `MAX_*` секций. Образцы — файлы, сохранённые редактором DTC.
2. Скопировать `aircraft/_template.lua` в `aircraft/<type>.lua`, заполнить `type`, `options`,
   `limits` (для каждой числовой опции) и `build(s, lib, opt)`.
3. Добавить тип в `AIRCRAFT` в `config.lua`. Ядро и `SarmatDTC.lua` трогать не нужно.
4. Добавить специфичные проверки в `tests/test_core.lua`, обновить эталоны (`-UpdateExpected`), прогнать тесты.

Выход для другой DTC-системы — элемент `outputs = { { id, format, dir, file, build } }` в модуле,
по умолчанию `enabled = false`. Новый формат файла — функция в `ENCODERS` в `SarmatDTC.lua`.
Альтернативный алгоритм заполнения — `variants` модуля, выбор через `OPTIONS[type].variant`.

## Тесты

```powershell
powershell -ExecutionPolicy Bypass -File "Scripts\SarmatDTC\tests\run_tests.ps1"
```

Параметры: `-DcsDir <папка DCS>` (иначе `DCS_DIR` или реестр), `-OutDir <папка>` — сохранить
сгенерированные DTC, `-UpdateExpected` — перезаписать эталоны (затем проверить дифф в git).

- `test_core.lua` — ядро и все модули: лимиты, сцепка линий, варианты, `limits` опций, битые данные,
  побайтное сравнение с эталонами `tests/fixtures/expected/`.
- `test_hook.lua` — `SarmatDTC.lua` с заглушками API DCS и реальной цепочкой `wscript → cmd → curl`
  по `file://`, из папки с кириллицей в пути.

Интерпретатор — `bin\luae.exe` из установки DCS (Lua 5.1). Тесты не запускают саму игру: изменения
в колбэках проверяйте на сервере по `dcs.log`. Сайт карты при отладке не нагружайте — есть фикстуры.

## Выпуск

Поднять `VERSION` в `SarmatDTC.lua` (видна в `dcs.log` игрока), прогнать тесты, проверить `file fetch.cmd`
(должен быть CRLF).
